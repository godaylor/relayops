# Ложная заглушка при отказе предзагрузки

Пользователь прислал снимок полноэкранной заглушки `startup-recovery` из своего Chrome. По одному снимку нельзя определить конкретный заблокированный URL. В изолированном Chrome воспроизведён такой же экран: после загрузки сводки блокируется `/assets/analytics-*.js`, затем достаточно навести мышь на «Аналитику». Навигация ещё не произошла, но общий обработчик Vite закрывал всю работающую страницу панелью восстановления.

Причина: защита первоначального запуска одинаково реагировала на критические стартовые ресурсы и необязательную предварительную загрузку после запуска React. Проверка обычного гостевого входа не моделировала этот отказ.

Исправление:

- После первого монтирования корневого маршрута React сообщает о готовности приложения. Последующие ошибки предзагрузки и посторонних CSS не вызывают глобальную заглушку.
- До монтирования обработчик проверяет, что сбой относится к собственным файлам приложения из `/assets/`. Ошибка внедрённого стиля или виджета сама по себе не считается отказом приложения. Этот ранний сценарий также воспроизведён отдельной падающей регрессией до исправления.
- Отказ критического стартового модуля или его зависимости по-прежнему даёт рабочую кнопку ручного обновления. Никакого автоматического сброса сессии, cookies или локальных данных не добавлено.
- Реальная навигация использует штатное восстановление TanStack Router: при недоступном модуле роутер может один раз обновить документ. Простая предзагрузка не перезагружает открытую страницу и не теряет ввод.
- JavaScript и CSS выпускаются под нейтральными именами с хешами (`app-*`, `chunk-*`, `asset-*`). Рабочие интерфейсные файлы больше не имеют `analytics` или `signal` в своём URL. Это уменьшает вероятность ошибочной блокировки функциональных ресурсов по имени; точное правило расширения в пользовательском Chrome не устанавливалось.

Регрессии проверяют заблокированный стартовый модуль на RU/EN, недоступную стартовую зависимость, сохранение фокуса и черновика при неудачной предзагрузке, посторонний CSS, рабочую сводку после отказа предзагрузки аналитики и переходы в сервисы/аналитику с блокировкой прежнего шаблона имён. Существующие проверки HTTP-кэша, 404 и защитных заголовков сохранены.
