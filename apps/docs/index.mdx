RelayOps — платформа для операционного реагирования на инциденты в реальном времени. Основная модель продукта: **Service → Signal → Incident → неизменяемая Timeline**.

## Основные возможности

- Operations Overview с текущим состоянием сервисов и активных инцидентов
- Incident Workbench с серверной фильтрацией и сохраняемыми представлениями
- Response Board с авторитетными переходами жизненного цикла
- Incident Room с участниками реагирования, сигналами и надёжной хронологией
- Service Catalog и аналитика надёжности
- API-авторизация по capability-наборам и восстановление состояния после realtime reconnect

## Техническая основа

Hono API остаётся источником доменной истины и авторизации, React-клиент использует типизированный API, PostgreSQL хранит долговечное состояние, а outbox и WebSocket-события поддерживают клиентов в актуальном состоянии. Redis опционален.

Технические руководства в этом разделе сохраняют совместимые имена пакетов, переменных среды и deployment identifiers Kaneo там, где их переименование могло бы нарушить обновление существующих установок.

## Происхождение

RelayOps создан на основе MIT-лицензированного проекта [Kaneo](https://github.com/usekaneo/kaneo), разработанного Andrej Acevski и сообществом Kaneo. RelayOps не является официальным продуктом Kaneo и не имеет официального одобрения Kaneo. Подробности — в корневых `LICENSE` и `README.md`.

Публичное имя RelayOps утверждено для некоммерческого portfolio/demo release. Формальная юридическая проверка товарного знака и домена не заявляется и остаётся отдельным условием коммерческого или полноценного production release.
